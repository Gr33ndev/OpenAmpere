# FoxESS H3, H3 Smart, H3 Pro

> Not official manufacturer information: compiled by the OpenAmpere contributors, possibly incomplete or wrong.
> Changing inverter settings can affect warranty and grid connection rules. No affiliation with FoxESS or EKD, not
> legal advice. See [Device knowledge](../README.md).

**Applies to:** FoxESS H3 (classic), H3 Smart, H3 Pro, three-phase hybrid inverters with battery · **Sold as:**
"Ampere.StoragePro E3" by EKD (which variant and register map is open) · **OpenAmpere:** driver `foxess`, register
maps `foxess_h3_new` ([h3-new-map.md](h3-new-map.md)) and `foxess_h3_legacy` ([h3-legacy-map.md](h3-legacy-map.md))
· **Support:** display and control · **Confirmed on a real device:** partly (H3 with newer firmware: reading and
control; older firmware, H3 Smart, H3 Pro: no)

## Summary

- One family, two register maps: newer firmware (and the H3 Smart and H3 Pro) use the new map with input registers,
  older firmware the legacy map with holding registers. OpenAmpere picks the map by which energy counters answer,
  not by the model string.
- The inverter allows only very few Modbus TCP connections at a time. When they are taken it accepts a connection and
  closes it at once. OpenAmpere should be its only Modbus client.
- Control uses holding registers: work mode, three SoC limits (outage floor, backup reserve, charge limit), the export
  limit (new map only) and a remote control with a watchdog timeout, which OpenAmpere uses for grid charging.
- The remote control has quirks: on a real H3 the switch stayed on after the watchdog expired
  ([#141](https://github.com/Gr33ndev/OpenAmpere/issues/141)), and according to foxess_modbus the inverter ignores its
  own charge limit during forced charging, so the software must stop by itself.
- Confirmed on a real H3 with newer firmware (new map): reading and all control features. The legacy map, the H3
  Smart and the H3 Pro are not confirmed yet.

## Decisions in OpenAmpere

| Decision | Why | Issue/PR |
|---|---|---|
| The model string is only a hint: the map is always confirmed by the counters (39601 → new map, else 32000 → legacy map), the new map is preferred, a device answering on neither is unsupported. A new-map model string answering only on the legacy map is logged as a warning. | Older H3 devices with newer firmware use the new map. | [driver.py](../../../src/openampere/drivers/foxess/driver.py), [docs/devices.md](../../devices.md) |
| The read function code is detected: the start of the map's last block is probed with the map's native code first (new FC04, legacy FC03), then the other one. | The sources disagree. | [driver.py](../../../src/openampere/drivers/foxess/driver.py) |
| Register map and read function can be chosen by hand (Mehr → Verbindung → Für Experten), e.g. behind a data logger that hides the model string. Settings are then written only if the model string matches a FoxESS pattern or the counter registers of that map answer; otherwise the device is read-only with a warning. | Before, any Modbus device at that address could receive settings and remote commands. | [#279](https://github.com/Gr33ndev/OpenAmpere/issues/279), [#280](https://github.com/Gr33ndev/OpenAmpere/issues/280) |
| The rated power from the model string limits the remote power (−rated..+rated W, 10 kW when unknown) and the export limit. | Plausibility limit before writing. | [driver.py](../../../src/openampere/drivers/foxess/driver.py) |
| OpenAmpere waits 1 s after connecting; a connection closed in that time is reported as "busy" ("Modbus-Gerät, gerade belegt", until [#433](https://github.com/Gr33ndev/OpenAmpere/issues/433) "Wechselrichter, gerade belegt") instead of an unknown device. Tested only against local test servers. | A FoxESS with all slots taken closes the connection before any request. | [#311](https://github.com/Gr33ndev/OpenAmpere/issues/311), [#312](https://github.com/Gr33ndev/OpenAmpere/issues/312) |
| The optional connection test opens 3 extra connections, reads 30000 on each and checks whether the main connection survived. | Shows whether other programs can read in parallel. | [diagnostics.py](../../../src/openampere/diagnostics.py), [#19](https://github.com/Gr33ndev/OpenAmpere/issues/19) |
| OpenAmpere stays the only Modbus client; Home Assistant gets data and control through OpenAmpere's external API. | Few connection slots; two writers would overwrite each other's settings. | [#76](https://github.com/Gr33ndev/OpenAmpere/issues/76), [#77](https://github.com/Gr33ndev/OpenAmpere/issues/77) |
| From Home Assistant at most 6 changes per hour per battery setting; the export limit and the remote power are not offered to Home Assistant. | Protects against looping automations and wear of the settings memory; the export limit is legally sensitive. | [#76](https://github.com/Gr33ndev/OpenAmpere/issues/76), [#77](https://github.com/Gr33ndev/OpenAmpere/issues/77), [docs/homeassistant.md](../../homeassistant.md) |
| Limits: 0 ≤ outage floor ≤ backup reserve < charge limit ≤ 100; the charge limit is at least 10 %. The reserve can be set from 10 % freely and below 10 % (down to the outage floor) only with an explicit confirmation every time, with a warning; Home Assistant cannot confirm. The driver's own check allows 0–100 % for floor and reserve, 10–100 % for the charge limit. | Owners' devices have 0 % as outage floor ([#69](https://github.com/Gr33ndev/OpenAmpere/issues/69)); a real H3 keeps a reserve below 10 % ([#313](https://github.com/Gr33ndev/OpenAmpere/issues/313)), but deep discharge can shorten battery life and affect the warranty. | [#69](https://github.com/Gr33ndev/OpenAmpere/issues/69), [#72](https://github.com/Gr33ndev/OpenAmpere/issues/72), [#313](https://github.com/Gr33ndev/OpenAmpere/issues/313), [#314](https://github.com/Gr33ndev/OpenAmpere/issues/314) |
| Limits are written one register at a time in an order that keeps every intermediate state valid. | A plain order can pass through an invalid set of limits. | [#203](https://github.com/Gr33ndev/OpenAmpere/issues/203), [#208](https://github.com/Gr33ndev/OpenAmpere/issues/208) |
| Every written setting is read back; the read-back is repeated after 1, 2 and 3 s before a mismatch is reported. Written values are read again 45 s and 150 s after a write. | Delayed take-over under remote control ([#322](https://github.com/Gr33ndev/OpenAmpere/issues/322)); the previous smartbox overwrites values about every 100 s ([#25](https://github.com/Gr33ndev/OpenAmpere/issues/25)). | [#322](https://github.com/Gr33ndev/OpenAmpere/issues/322), [#323](https://github.com/Gr33ndev/OpenAmpere/issues/323), [control.py](../../../src/openampere/control.py) |
| The export limit can only be raised with control enabled and the declaration that the grid operator's written approval is on hand; its reference is logged. Lowering is always possible. | The limit is part of the grid connection approval. | [docs/registers.md](../../registers.md), [control.py](../../../src/openampere/control.py) |
| Grid charging uses the remote control with a 180 s watchdog and re-sends the command; order timeout → enable → power. | No scheduled charging registers; the watchdog ends charging if OpenAmpere stops. | [charging.py](../../../src/openampere/charging.py), [driver.py](../../../src/openampere/drivers/foxess/driver.py) |
| Grid charging levels are 50/75/100 % of a configurable permitted battery charge power (from the datasheet), capped at the inverter's power; higher values are rejected. | The earlier 30/60/100 % of the inverter's power was too much for small batteries. | [#23](https://github.com/Gr33ndev/OpenAmpere/issues/23), [#49](https://github.com/Gr33ndev/OpenAmpere/issues/49) |
| Grid charging charges only up to min(target, inverter's charge limit); the charge limit is read at most every 10 minutes (100 % if unreadable) and the remote control is released when it is reached. | The inverter ignores its charge limit during forced charging. | [#242](https://github.com/Gr33ndev/OpenAmpere/issues/242), [#246](https://github.com/Gr33ndev/OpenAmpere/issues/246) |
| Once per session, 90 s after the first command, OpenAmpere checks that the battery charges. Not charging within 5 % below the inverter's charge limit pauses without error (restart after the SoC dropped by 5 %); not charging far below it is a fault (stop, error, grid charging off). | A normal end of charge must not count as a fault; the sign is not verified on every device. Simulator tests. | [#218](https://github.com/Gr33ndev/OpenAmpere/issues/218), [#225](https://github.com/Gr33ndev/OpenAmpere/issues/225) |
| A refused remote command releases OpenAmpere's own remote command at once, logs "Befehl abgelehnt" and is not retried in the same quarter hour. | A half-applied command must not leave the remote control on. | [#258](https://github.com/Gr33ndev/OpenAmpere/issues/258), [#261](https://github.com/Gr33ndev/OpenAmpere/issues/261) |
| Grid charging tick and stop are serialised with a lock. | A stop during a running tick must not be followed by the tick switching the remote control on again. | [#271](https://github.com/Gr33ndev/OpenAmpere/issues/271), [#272](https://github.com/Gr33ndev/OpenAmpere/issues/272) |

## Open questions

- Which register map the "Ampere.StoragePro E3" uses and which FoxESS variant it is; to check with the model string at
  30000 ([docs/registers.md](../../registers.md)).
- Function code of the new map: foxess_modbus reads it with FC03, other sources with FC04 (conflict; OpenAmpere tries
  both).
- **Conflict, watchdog:** foxess_modbus says the watchdog ends remote control after the timeout; on one owner's H3 the
  enable stayed 1 with 0 W long after it ([#141](https://github.com/Gr33ndev/OpenAmpere/issues/141)). Whether the
  watchdog only drops the power, or does nothing on some firmware, is unclear.
- **Conflict, restore after restart:** [#297](https://github.com/Gr33ndev/OpenAmpere/issues/297) and [AGENTS.md](../../../AGENTS.md) state
  as a fact that the inverter brings back its remote command values after a restart, while
  [#143](https://github.com/Gr33ndev/OpenAmpere/issues/143) and [docs/registers.md](../../registers.md) call it
  suspected and not verified. Treated as open here.
- Does the inverter accept 0 % for the outage floor written via Modbus? A rejection would show in the read-back
  ([#72](https://github.com/Gr33ndev/OpenAmpere/issues/72)).
- Sign of the remote power setpoint on every device (negative = charging).
- Why grid charging stops at the backup reserve when the battery starts below it
  ([#320](https://github.com/Gr33ndev/OpenAmpere/issues/320)).
- Reaction to an active remote command during a power cut ([#242](https://github.com/Gr33ndev/OpenAmpere/issues/242)).
- What a lost grid meter ("Meter Lost") does on the H3: alarm only, or switching off as on the H1.
- Whether an H3 runs normally for weeks without the previous smartbox, and whether the box's remote control ends by
  itself when the box is cut off in the middle of a command ([iq-box.md](../topics/iq-box.md)).
- Whether the grid meter values are still delivered when the inverter is switched off at its AC switch, so the 100 W
  check catches it ([#93](https://github.com/Gr33ndev/OpenAmpere/issues/93)).
- Whether some newer firmware counts energy in 0.1 kWh steps although the unit is 0.01 kWh
  ([#194](https://github.com/Gr33ndev/OpenAmpere/issues/194)), and whether the daily counters reset without daylight
  saving time.
- Which variants have the export limit register: foxess_modbus names only the H3 Smart, it worked on a new-map device
  whose exact variant is not stated ([#196](https://github.com/Gr33ndev/OpenAmpere/issues/196)).
- How many Modbus connections a given system allows; the busy detection is tested only against local test servers
  ([#312](https://github.com/Gr33ndev/OpenAmpere/issues/312)).
- Reading and control on the legacy map, the H3 Smart and the H3 Pro are not confirmed on a real device
  ([#196](https://github.com/Gr33ndev/OpenAmpere/issues/196), [#197](https://github.com/Gr33ndev/OpenAmpere/issues/197)).
